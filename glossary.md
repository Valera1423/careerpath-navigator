# Глоссарий

Словарь терминов для жюри, инвесторов и новых пользователей. Включает как специфичные для проекта понятия, так и общие технические термины.

---

## 🎯 Продуктовые термины

### CareerPath Navigator
Мини-приложение в MAX, помогающее студентам и выпускникам понять, какие навыки нужны для желаемой должности, и построить план карьерного развития.

### Mini App
Приложение, встроенное внутрь мессенджера MAX. Открывается по кнопке из чата с ботом. Работает по HTTPS-ссылке.

### MAX
Российский национальный мессенджер. Поддерживает ботов, Mini App, платежи. Аналог Telegram, но с российской инфраструктурой.

### MAX Bridge
JavaScript-библиотека, через которую Mini App общается с клиентом MAX. Передаёт данные пользователя (`initData`), открывает нативные экраны, управляет настройками.

### MAX Bot API
REST API для управления ботами. Методы: отправка сообщений, inline-клавиатуры, подписка на события (webhook).

## 🧠 Предметная область

### Skill Gap
Разрыв между текущими навыками пользователя и требованиями рынка для желаемой должности. Показывает, чего именно не хватает.

### Readiness Score
Оценка готовности к роли (0–100%). Взвешенный процент покрытых навыков из топ-требований вакансий.

### Missing Skills
Навыки из требований рынка, которых у пользователя нет. Отсортированы по важности (`critical`, `important`, `nice-to-have`).

### Matched Skills
Навыки пользователя, которые встречаются в требованиях вакансий. Используются для расчёта match score.

### Match Score
Процент совпадения навыков пользователя с требованиями конкретной вакансии (0–100%).

### Gap-анализ
Процесс сравнения навыков пользователя с требованиями рынка. На основе анализа строится персональный план.

### План развития
Последовательность шагов для закрытия skill gap. Каждый шаг — курс или проект с ресурсом.

### Readiness
Общая готовность пользователя к роли. Разница между 100% и readiness_score — это и есть skill gap.

## 🗄️ Источники данных

### «Работа России»
Государственная платформа с открытыми данными о вакансиях. API: `opendata.trudvsem.ru/api/v1/vacancies`. Не требует токена.

### HH.ru API
Публичное API hh.ru. С 2026 требует OAuth-токен для большинства методов. Опционально подключается к проекту.

### Fallback-данные
Тестовый набор вакансий, который используется, если внешние API недоступны. Помечается флагом `source: "fallback"` в ответе.

### TTL-кэш
Кэш с временем жизни (Time To Live). В проекте — 8 часов для выдачи «Работы России».

## 👤 Роли пользователей

### Студент
Основная аудитория. 18–25 лет. Ищет первую работу или стажировку. Проходит онбординг, получает план, работает с вакансиями.

### Школьник
Дополнительная аудитория. 8–11 класс. Проходит RIASEC-тест, узнаёт профессии, пробует «примерочную».

### Работодатель
B2B-клиент. Подключается через Employer API. Видит анонимизированные профили студентов с их согласия.

### Вуз
B2B-клиент (в планах). Получает агрегированную аналитику по студентам и кастомные треки.

### Ментор
Опытный специалист. Проводит сессии со студентами, оставляет верифицированные отзывы (в планах).

## 🤖 AI / LLM

### AI-коуч
Чат-бот, отвечающий на вопросы про навыки. Использует контекст профиля + LLM (опционально) + шаблоны.

### STAR-метод
Структура ответа на собеседовании: **S**ituation (ситуация) — **T**ask (задача) — **A**ction (действие) — **R**esult (результат). Используется для оценки ответов в симуляторе интервью.

### STAR-оценка
Алгоритм проверки ответа на наличие 4 компонентов STAR. Возвращает 0–10 баллов и рекомендации.

### LLM
Large Language Model — большая языковая модель (GPT-4, Claude и др.). Используется для AI-коуча, если задан `LLM_API_KEY`.

### RAG
Retrieval-Augmented Generation — подход, при котором LLM дополняется релевантными документами из базы. Планируется в v2.0.

### Fallback
Резервный сценарий. Если LLM недоступна — используется шаблонный ответ.

## 🔒 Безопасность и право

### initData
Строка от MAX Bridge с данными пользователя. **Валидируется на backend** через HMAC-SHA256 с бот-токеном. TTL — 1 час.

### initDataUnsafe
JSON-объект тех же данных. **Нельзя использовать для аутентификации.** Только для UI-подсказок.

### HMAC-SHA256
Алгоритм подписи. Используется для проверки подлинности initData.

### 152-ФЗ
Федеральный закон «О персональных данных». Регулирует сбор, хранение и передачу ПДн. Требует согласия субъекта.

### PII
Personally Identifiable Information — персональные данные: ФИО, email, телефон, точный ID.

### Anonymization (анонимизация)
Удаление или замена PII перед передачей третьим лицам. В Employer API передаётся только регион (округ) и навыки.

### Opt-in
Явное согласие пользователя на передачу данных. По умолчанию выключено. Управляется в настройках.

### Consent (согласие)
Обязательный чекбокс при онбординге. Фиксируется в `consent_pd_given_at`.

### Rate limiting
Ограничение частоты запросов. Защита от злоупотреблений и DDoS.

### CORS
Cross-Origin Resource Sharing. Механизм безопасности браузера. Backend разрешает только домены фронтенда.

## 🛠️ Технические термины

### FastAPI
Современный Python-фреймворк для API. Async, автоматический Swagger, Pydantic-валидация.

### Pydantic
Библиотека валидации данных через типы. Используется для DTO и настроек.

### SQLAlchemy
ORM для Python. Модели → таблицы БД. Используется в синхронном режиме.

### Alembic
Миграции БД для SQLAlchemy. Каждое изменение схемы — отдельная миграция с `upgrade` и `downgrade`.

### PostgreSQL
Реляционная БД. В проекте — managed на Neon (free-tier).

### Neon
Serverless-хостинг PostgreSQL. Free-tier: 0.5 ГБ, автоскейл, автосон.

### Webhook
HTTP-запрос от MAX к нашему backend при событии (например, новом сообщении). Требует HTTPS на 443.

### Long polling
Альтернатива webhook: клиент постоянно опрашивает сервер. **Не подходит для production MAX** — ограничен по скорости и сроку хранения событий.

### ASGI
Асинхронный интерфейс для Python-веб-серверов. FastAPI — ASGI-приложение. Запускается через uvicorn.

### Uvicorn
ASGI-сервер. Запускает FastAPI-приложение.

### Docker
Контейнеризация. Backend и frontend упакованы в образы, запускаются через `docker compose`.

### Docker Compose
Оркестрация нескольких контейнеров. В проекте — `compose.yaml`.

### Vercel
Хостинг для фронтенда. Автоматический деплой из GitHub, HTTPS из коробки.

### Wispbyte
Хостинг для backend. Pterodactyl-панель, Docker-образы. Free-tier: 512 МБ RAM.

## 🎓 Образовательный трек

### RIASEC
Методика профессиональных склонностей по Голланду. 6 типов: **R**ealistic, **I**nvestigative, **A**rtistic, **S**ocial, **E**nterprising, **C**onventional.

### Примерочная профессии
Интерактивный сценарий «Один день из жизни» для роли (аналитик, разработчик, дизайнер).

### Day-in-the-life
Формат симулятора: пользователь «проживает» рабочий день в роли через серию решений.

### Симулятор интервью
5 вопросов по роли с таймером и STAR-оценкой ответа.

### ATS
Applicant Tracking System — система автоматического отбора резюме. Анализ проверяет, пройдёт ли резюме через неё.

### Keyword matching
Совпадение ключевых слов из вакансии с резюме. Основа ATS-анализа.

## 🧩 Employer API (B2B)

### API-ключ
Секретный токен для доступа к Employer API. Формат: `cp_<32 символа>`. Хранится как bcrypt-хэш.

### Candidate ID
Анонимный идентификатор студента. SHA256 от user_id, 16 символов. Не раскрывает личность.

### Verified Skill
Навык, подтверждённый артефактом: GitHub-репозиторий, сертификат, задеплоенный проект.

### HR Open Standards 4.5RCI
Международный стандарт для обмена данными о кандидатах. Основа для Employer API.

### LER-RS
Learning and Employment Record — Resume Standard. Стандарт верифицируемых записей о навыках. Целевой формат для v2.0.

### ARP
Agentic Recruitment Protocol. Открытый стандарт для AI-агентов в найме. Потенциальная интеграция.

## 📊 Инфраструктура

### Prometheus
Система сбора метрик. Backend экспортирует `/metrics`, Prometheus скрейпит.

### Grafana
Визуализация метрик из Prometheus. Дашборды по latency, RPS, ошибкам.

### Sentry
Сервис отслеживания ошибок на фронте и бэке. В планах на v1.1.

### CI (Continuous Integration)
Автоматические проверки при push. В проекте — GitHub Actions: ruff, mypy, pytest, tsc, build.

### CD (Continuous Deployment)
Автоматический деплой после merge. Vercel делает это для фронта, Wispbyte — вручную.

### Healthcheck
Эндпоинт `/health`, отвечающий `{"status":"ok"}`. Используется монитором и Docker.

### Latency
Задержка ответа. Основная метрика производительности.

### p95 / p99
95-й и 99-й процентиль latency. «95% запросов быстрее, чем X мс».

## 💰 Бизнес-термины

### B2C
Business to Consumer — продукт для конечных пользователей. В проекте — подписка для студентов.

### B2B
Business to Business — продукт для компаний. В проекте — white-label для вузов и Employer API для HR.

### B2G
Business to Government — продукт для государства. В проекте — интеграция с «Билет в будущее».

### White-label
Продукт под брендом клиента. Вуз может выпустить наш сервис со своим логотипом и доменом.

### MAU / DAU
Monthly / Daily Active Users. Метрики активной аудитории.

### Retention D7 / D30
Процент пользователей, вернувшихся через 7 / 30 дней. Ключевая метрика удержания.

### NPS
Net Promoter Score. Метрика лояльности: «Готовы ли вы рекомендовать продукт?»

### Unit economics
Экономика единицы продукта: сколько стоит привлечь пользователя vs сколько он приносит.

### LTV / CAC
Lifetime Value / Customer Acquisition Cost. Отношение должно быть ≥ 3.

## Часто задаваемые вопросы

**Что такое «Работа России»?**  
Государственная платформа с открытыми данными о вакансиях. Мы берём оттуда требования рынка.

**Что значит "fallback" в ответе API?**  
Значит, что реальный API недоступен, и мы отдали тестовый набор. В UI это показывается жёлтым уведомлением.

**Почему MAX, а не Telegram?**  
Трек хакатона — MAX. Плюс MAX — российский мессенджер с господдержкой, что даёт потенциал для масштабирования.

**Как я могу проверить проект?**  
Откройте бота `@se14433704_bot` в MAX → `/start` → «Открыть мини-приложение».

GitHub Issues: `github.com/Valera1423/careerpath-navigator/issues`.
